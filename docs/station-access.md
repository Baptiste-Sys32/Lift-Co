# Station sides and passenger circulation

The local sandbox exposes two exterior connections at every passenger station: Left access and Right access. Each side is outside the station footprint with room for a wide piste. These are explicit snap targets. Multiple pistes and footpaths can share either connection; no connection is replaced when another run is added.

Connections use stable IDs such as `lift-id:top:left` and `lift-id:top:right`. Both connect to the existing logical station node through station walking edges, with walking distance included in routing costs. Existing `lift-id:top` connections retain their original position and remain valid. Their original snap is retained internally for editing and save compatibility, while the map offers the two exterior rings for new construction. Resort documents remain version 3; the IDs travel through the existing snapshots, backup-gated writes and history.

`src/resort/station-access.js` owns terminal geometry, side points and local pedestrian routes. Routes use the terminal envelope and exterior corners rather than a straight line across the machinery. Native same-side boarding platforms remain accessible. Central platforms in reversible stations leave along the end of the terminal rather than crossing a cabin lane. Enclosed Princesse stations use the rear entrance approach. Navigation is a local terminal-envelope model, not a full building-interior navigation mesh.

Queue entry, loading approaches and post-unload exits follow these waypoints. When a passenger's next connection is a piste on a selected side, unloading proceeds directly to that side without visiting an unnecessary intermediate point. Existing footpaths that cross a terminal on their last approach are compiled into a visible detour around it. Snow approaches on old pistes use the same navigation when station earthworks need to be crossed. Explicit hand-drawn routes away from terminal approaches are preserved.

Circulating lifts require the correct destination station, incoming passenger lane, a valid unloading window, low cabin speed for gondolas and at least 92 percent door/bar opening before guests leave. Reversible cabins also require docking, near-zero speed and enough dwell remaining to complete the exit before doors close. Boarding uses the same open-door requirement. A closed boarding operation still lets existing passengers unload.

The guest retains the assigned seat throughout the exit animation. The seat is freed only on reaching the platform, and the interpolation follows the moving cabin. Platform heights are used at unloading and while waiting, preventing guests from dropping into the deck. Legacy circulating lift arrival gates and platform sides now consistently describe the named destination station in both directions. Missing carriers are handled by relocating the guest through the existing reset path.

Focused isolated scenarios cover six lift families, rotated terminals, passenger mid-stations, both side IDs, perimeter paths, old footpath detours, three pistes sharing a station, opposite-side returns and V3 reload. Door scenarios cover closed and partial opening, wrong stations, departure lanes and closing dwell. Guest scenarios verify retained seats during unloading, platform touchdown, physical movement around the terminal and direct continuation to the selected piste side. Native legacy gate definitions are inspected in both directions. Existing skier motion, snow approaches, nature planting and construction history scenarios remain checked. No repository test suite was added or run. Browser visual review and device performance remain unverified when browser control is unavailable.
